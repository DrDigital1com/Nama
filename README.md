# Nama — ערכת בדיקה ואבחון ל-WordPress / WooCommerce

ערכת כלים ותיעוד לבדיקה מלאה של `nama-c.com`: איתור תקלות, שיפור מהירות, ואבחון בעיית **ההזמנות הלא מושלמות**.

---

## ⚠️ הבהרה חשובה

הבדיקה **לא בוצעה על האתר החי**. סביבת ההרצה חוסמת גישת רשת ל-`nama-c.com` (מדיניות egress — 403 על CONNECT; גם fetch מנוהל החזיר `EGRESS_BLOCKED`), והריפו הגיע ריק לחלוטין — ללא קוד תבנית או תוספים.

מה שיש כאן הוא **הערכה שמריצה את הבדיקה עבורך על האתר**, ומוציאה בדיוק את הנתונים הדרושים לניתוח.
פרטים ומה שנדרש כדי להמשיך: [`ACCESS-NEEDED.md`](ACCESS-NEEDED.md).

---

## התחלה מהירה — 10 דקות

1. **לגבות את האתר** (קבצים + בסיס נתונים).
2. להעלות את `tools/nama-audit.php` אל `wp-content/mu-plugins/`.
3. בלוח הבקרה: **כלים → Nama Audit → הרצת בדיקה מלאה**.
4. לקרוא את הממצאים המסומנים **קריטי**, ולהעתיק את ה-JSON מתחתית העמוד.

לאבחון ההזמנות, להוסיף גם את `tools/nama-checkout-logger.php` לאותה תיקייה ולהמתין 24–48 שעות.

## הבדיקה שכדאי להתחיל ממנה

מכל הכלים כאן, אחד מקצר את האבחון יותר מכולם: **בדיקה A7** ב-`sql/orders-diagnostics.sql`.

היא מחפשת הזמנות בסטטוס `pending`/`failed` **שיש להן `transaction_id`**.

- **יש תוצאות** → לקוחות שילמו וההזמנה לא עודכנה. ה-callback משער הסליקה נחסם או לא מגיע. → [פלייבוק, שלב 1](docs/02-incomplete-orders.md)
- **אין תוצאות** → הלקוחות לא הגיעו לתשלום. הבעיה מוקדמת יותר. → [פלייבוק, שלב 2](docs/02-incomplete-orders.md)

שתי התוצאות מובילות לתיקונים שונים לחלוטין. שווה 5 דקות לפני כל דבר אחר.

## פרטיות ובטיחות

- כל הכלים כאן הם **קריאה בלבד**. אף אחד מהם לא משנה הגדרות, לא מוחק נתונים ולא מעדכן הזמנות.
- ייצוא ה-JSON **אינו כולל** שמות, מיילים, כתובות, טלפונים או פרטי תשלום. כתובות IP נשמרות מגובבות בלבד.
- הפקודות שמופיעות בתיעוד ומשנות משהו (ניקוי, `wp db optimize`, עדכון סטטוס) מסומנות ומלוות באזהרת גיבוי.
- **לא לשלוח בערוץ הזה** סיסמאות, מפתחות API של שער הסליקה, או תוכן `wp-config.php`.

## דרישות

WordPress 5.9+ · WooCommerce 6.0+ · PHP 7.4+ (מומלץ 8.1+). הכלים תומכים גם ב-HPOS וגם באחסון ההזמנות המסורתי, ובצ׳קאאוט קלאסי וגם בצ׳קאאוט בלוקים.
