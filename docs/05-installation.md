# התקנה ופתרון בעיות

## הדרך המומלצת — התקנה כתוסף רגיל (ZIP)

1. **תוספים → הוספת תוסף → העלאת תוסף**
2. לבחור את `dist/nama-audit.zip`
3. **התקן עכשיו** → **הפעלת התוסף**
4. בסרגל הצד יופיע **Nama Audit** (וגם תחת **כלים**)
5. **הרצת בדיקה מלאה** → להעתיק את ה-JSON מתחתית העמוד

אותו דבר עבור `dist/nama-checkout-logger.zip` (אבחון ההזמנות).

---

## אם התפריט לא מופיע — יש גישה ישירה שלא תלויה בו

הדרך הבטוחה ביותר היא פשוט להיכנס לכתובת. היא עוקפת את תפריט הניהול לגמרי:

| כתובת | מה היא עושה |
|---|---|
| `/wp-admin/?nama_audit=1` | מריצה ומציגה את הדוח המלא |
| `/wp-admin/?nama_audit=json` | מחזירה JSON גולמי — נוח לשמור ולשלוח |
| `/wp-admin/?nama_audit=ping` | בדיקה מהירה שהתוסף בכלל נטען |

בנוסף, במסך **תוספים** מופיע קישור **"הרצת בדיקה"** בשורת התוסף עצמו.

חובה להיות מחובר כמנהל מערכת; אחרת מתקבלת הודעת "אין הרשאה".

---

## אם גם זה לא עובד

לפי סדר השכיחות:

### 1. הקובץ הונח בתיקיית משנה
זו הסיבה הנפוצה ביותר בהתקנת mu-plugin. וורדפרס טוענת רק קבצי PHP **ישירות** בתוך `mu-plugins/`, בלי לרדת לתיקיות משנה.

```
✅ wp-content/mu-plugins/nama-audit.php
❌ wp-content/mu-plugins/nama-audit/nama-audit.php
❌ wp-content/plugins/nama-audit.php   (כאן צריך להפעיל דרך מסך התוספים)
```

**הפתרון:** להשתמש ב-ZIP ובהתקנה רגילה. זה עוקף את כל הבעיה.

### 2. אין הרשאת מנהל
התפריט דורש הרשאת `manage_options` — כלומר **מנהל מערכת (Administrator)**.
מנהל חנות (Shop Manager) או עורך **לא יראו** את התפריט.

בדיקה: **משתמשים → הפרופיל שלי** — התפקיד חייב להיות "מנהל מערכת".

### 3. התוסף הותקן אך לא הופעל
**תוספים → תוספים מותקנים** → לחפש "Nama Audit" → **הפעלה**.

### 4. גרסת PHP נמוכה מ-7.4
הקוד דורש PHP 7.4 ומעלה. בגרסה ישנה יותר וורדפרס תדלג עליו בשקט.

בדיקה: **כלים → בריאות האתר → מידע → שרת → גרסת PHP**.

### 5. שגיאה בעת הטעינה
אם יש שגיאה, וורדפרס עלולה להשבית את התוסף אוטומטית ולשלוח מייל למנהל.
לבדוק את תיבת המייל של מנהל האתר, ואת **כלים → בריאות האתר**.

### 6. תיקיית mu-plugins לא במקום ברירת המחדל
במקרים נדירים `WPMU_PLUGIN_DIR` מוגדר אחרת ב-`wp-config.php`.
לחפש שם את השורה `WPMU_PLUGIN_DIR` — אם היא קיימת, זה הנתיב האמיתי.

## גיבוי לפני הכל

לפני התקנת כל תוסף בסביבת ייצור — **גיבוי מלא של הקבצים ובסיס הנתונים**.
שני התוספים כאן הם קריאה בלבד ולא משנים דבר, אבל הכלל לא משתנה.

---

## אם אין גישה להעלאת תוספים

להעלות דרך FTP/File Manager אל:
```
wp-content/plugins/nama-audit/nama-audit.php
```
(תיקייה בשם `nama-audit`, ובתוכה הקובץ). ואז **תוספים → הפעלה**.
