# הגדרת שליחת מיילים דרך SMTP של השרת

**המצב:** WP Mail SMTP מוגדר כרגע מול Google API, וההרשאה נכשלת. לקוחות ששילמו לא מקבלים אישור הזמנה (#10568, #10616, #10623), והמנהל לא מקבל התראות ביטול.

**היעד:** שליחה דרך שרת הדואר של האחסון (cPanel), עם אימות תקין כדי שהמיילים לא ייפלו לספאם.

---

## שלב 0 — שתי מלכודות Cloudflare

האתר מאחורי Cloudflare. שתי נקודות שחייבות להיות נכונות, אחרת שום הגדרה לא תעבוד:

### א. רשומת ה-mail חייבת להיות DNS only

**Cloudflare → DNS → Records** → לחפש את הרשומה `mail`:

| מצב | משמעות |
|---|---|
| 🟠 ענן כתום (Proxied) | **החיבור ייכשל.** Cloudflare מעביר רק HTTP/HTTPS, לא SMTP |
| ⚪ ענן אפור (DNS only) | ✅ תקין |

אם היא כתומה — ללחוץ על הענן ולהפוך אותו לאפור. גם רשומת ה-`autodiscover` ורשומות ה-MX (ל-MX אין בכלל אפשרות proxy).

### ב. ה-DNS לא ב-cPanel — הכפתור האוטומטי לא יעבוד

ב-cPanel יש **Email Deliverability** עם כפתור "Repair"/"תקן". הוא **לא יעזור כאן**, כי הוא כותב לשרת השמות של cPanel — ואילו הדומיין שלך מצביע על Cloudflare.

מה שהוא כן טוב אליו: **להראות לך את הרשומות המדויקות שצריך.** מעתיקים אותן משם, ומדביקים ידנית ב-Cloudflare.

## שלב 1 — ליצור תיבת דואר ייעודית

**cPanel → Email Accounts → Create**

| שדה | ערך |
|---|---|
| Username | `no-reply` |
| Domain | `nama-c.com` |
| Password | ליצור סיסמה חזקה (16+ תווים) ולשמור במנהל סיסמאות |
| Storage | 1GB מספיק |

> **למה תיבה ייעודית ולא תיבה קיימת:** אם הסיסמה של התיבה תתחלף, רק המיילים האוטומטיים יישברו ולא הדואר האישי שלך. וגם — הסיסמה תישמר בשרת האתר, אז עדיף שלא תהיה של תיבה אמיתית שקוראים בה דואר.

## שלב 2 — לאסוף את פרטי החיבור

**cPanel → Email Accounts → ליד התיבה החדשה → Connect Devices**

שם מופיעים הערכים המדויקים של השרת שלך. מה שצריך:

| פרט | היכן מופיע | ערך טיפוסי |
|---|---|---|
| **SMTP Host** | Outgoing Server | `mail.nama-c.com` |
| **SMTP Port** | Outgoing Server | `465` (SSL) או `587` (TLS) |
| **Encryption** | | SSL / TLS |
| **Username** | | `no-reply@nama-c.com` — **הכתובת המלאה**, לא רק `no-reply` |
| **Password** | | הסיסמה שיצרת |

**באיזה פורט לבחור:** להתחיל עם **465 + SSL**. זה מה שרוב שרתי cPanel מעדיפים. אם נכשל — לנסות **587 + TLS**.

> ⚠️ אם ה-Host שמופיע ב-Connect Devices הוא לא `mail.nama-c.com` אלא שם אחר (למשל `server123.hostname.com`) — **להשתמש במה שמופיע שם.** זה חשוב לתעודת ה-SSL: אם השם לא תואם לתעודה, החיבור ייכשל באימות.

## שלב 3 — להגדיר ב-WP Mail SMTP

**WP Mail SMTP → Settings**

### From Email / From Name
| שדה | ערך |
|---|---|
| From Email | `no-reply@nama-c.com` |
| Force From Email | ✅ **לסמן** |
| From Name | `NAMA` |
| Force From Name | ✅ לסמן |

> **`Force From Email` הוא קריטי.** בלעדיו תוספים אחרים (ווקומרס, MC4WP, Elementor Forms) שולחים כל אחד מכתובת אחרת. כתובת שליחה שלא תואמת ל-SPF שהגדרת = ספאם.

### Mailer
לבחור **Other SMTP**, ולמלא:

| שדה | ערך |
|---|---|
| SMTP Host | `mail.nama-c.com` (או מה שהופיע ב-Connect Devices) |
| Encryption | **SSL** |
| SMTP Port | **465** |
| Auto TLS | ✅ פעיל |
| Authentication | ✅ פעיל |
| SMTP Username | `no-reply@nama-c.com` |
| SMTP Password | הסיסמה |

### הסיסמה — עדיף לא בבסיס הנתונים

WP Mail SMTP שומר את הסיסמה בטבלת `options` בטקסט גלוי. עדיף להגדיר אותה כקבוע ב-`wp-config.php`, **לפני** השורה `/* That's all, stop editing! */`:

```php
define( 'WPMS_ON', true );
define( 'WPMS_SMTP_PASS', 'הסיסמה-כאן' );
```

אחרי זה שדה הסיסמה בממשק יינעל ויציין שהערך מגיע מקובץ. הסיסמה כבר לא תופיע בגיבוי של בסיס הנתונים.

## שלב 4 — DNS: SPF, DKIM, DMARC

**בלי אלה המיילים יגיעו לספאם.** במיוחד ל-Gmail ול-Outlook, ובמיוחד משרת אחסון משותף.

### מאיפה לוקחים את הערכים
**cPanel → Email Deliverability → ליד `nama-c.com` → Manage**
שם מוצגות רשומות ה-SPF וה-DKIM המדויקות של השרת שלך. **להעתיק משם.**

### להוסיף ב-Cloudflare
**Cloudflare → DNS → Records → Add record**

**SPF** (רשומת TXT אחת בלבד לדומיין — אם כבר קיימת, לערוך ולא להוסיף שנייה):
```
Type:  TXT
Name:  @
Value: v=spf1 +a +mx +ip4:<כתובת ה-IP של השרת> ~all
```

**DKIM** (להעתיק את הערך המלא מ-cPanel — הוא ארוך):
```
Type:  TXT
Name:  default._domainkey
Value: v=DKIM1; k=rsa; p=<המפתח הארוך מ-cPanel>
```

**DMARC** (להתחיל ברך, לא לחסום):
```
Type:  TXT
Name:  _dmarc
Value: v=DMARC1; p=none; rua=mailto:admin@nama-c.com; pct=100
```

> `p=none` אומר "רק תדווח, אל תחסום". אחרי חודש של מעקב אפשר להחמיר ל-`p=quarantine`.

### לאמת שהתפרסם
```bash
dig +short TXT nama-c.com
dig +short TXT default._domainkey.nama-c.com
dig +short TXT _dmarc.nama-c.com
```
או דרך https://mxtoolbox.com/spf.aspx

הפצת DNS לוקחת בין דקות לשעה.

## שלב 5 — בדיקה

### א. בדיקה בסיסית
**WP Mail SMTP → Tools → Email Test** → להזין כתובת Gmail אישית → **Send Email**

- ✅ הצלחה → להמשיך לב׳
- ❌ כישלון → ראה טבלת השגיאות למטה

### ב. לבדוק שהאימות עובד (חשוב!)
המייל הגיע? מצוין. עכשיו לבדוק שהוא הגיע **מאומת**:

ב-Gmail: לפתוח את המייל → תפריט ⋮ → **Show original**

צריך להופיע:
```
SPF:   PASS
DKIM:  PASS
DMARC: PASS
```

שלושתם PASS = המיילים ינחתו בתיבה הראשית. אם אחד FAIL — לחזור לשלב 4.

### ג. ציון דירוג
לשלוח מייל בדיקה לכתובת שמייצר https://www.mail-tester.com — הוא נותן ציון מ-10 ומפרט בדיוק מה חסר. **יעד: 9/10 ומעלה.**

### ד. בדיקה אמיתית מקצה לקצה
1. לבצע הזמנת בדיקה בחנות
2. לוודא שהתקבל `customer_processing_order` אצל הלקוח
3. לוודא שהתקבלה התראה אצל המנהל
4. **WooCommerce → סטטוס → יומנים → `transactional-emails`** — אפס שורות `failed to send`

## טבלת שגיאות

| השגיאה | הסיבה | התיקון |
|---|---|---|
| `Connection timed out` / `Could not connect` | פורט 465 חסום ביציאה מהשרת | לנסות 587+TLS. אם גם נכשל — לפנות לאחסון: *"האם יציאת SMTP חסומה לחשבון שלי?"* |
| `SSL certificate problem` / `Hostname mismatch` | ה-Host לא תואם לתעודת השרת | להשתמש בשם שמופיע ב-Connect Devices, ולא ב-`mail.nama-c.com` |
| `SMTP Error: Could not authenticate` | שם משתמש או סיסמה | ה-Username חייב להיות **הכתובת המלאה** `no-reply@nama-c.com`. לוודא סיסמה מול cPanel |
| `Connection refused` על 465 | השרת מצפה ל-TLS ולא ל-SSL | לעבור ל-587 + TLS |
| נשלח אך מגיע לספאם | SPF/DKIM חסרים או שגויים | שלב 4, ואז לבדוק ב-mail-tester |
| נשלח, SPF FAIL | `Force From Email` לא מסומן | לסמן אותו. כתובת השליחה חייבת להיות בדומיין שה-SPF מכסה |
| עובד ואז מפסיק אחרי X מיילים | מכסת שליחה יומית של האחסון | לבדוק מול האחסון מה המכסה. אם קטנה — לשקול ספק ייעודי |

## מה לצפות ממנו, ומתי לשקול משהו אחר

SMTP של שרת אחסון משותף עובד, אבל יש לו שתי מגבלות מובנות:

1. **מוניטין IP משותף.** אתה חולק כתובת IP עם עוד אתרים על אותו שרת. אם אחד מהם שולח ספאם — המוניטין נפגע גם לך.
2. **מכסת שליחה יומית.** רוב חבילות האחסון מגבילות ל-200–500 מיילים ליום.

בהיקף שלך (כ-50 הזמנות בחודש) זה בהחלט מספיק. **אם** בעתיד תראה מיילים שנופלים לספאם למרות SPF/DKIM תקינים, או שתגדל משמעותית — אז שווה לעבור לספק ייעודי (Brevo נותן 300 ביום בחינם, SendLayer, Postmark). זה שינוי של 10 דקות באותו מסך של WP Mail SMTP.

לבינתיים: SMTP של השרת עם SPF+DKIM תקינים זו הגדרה לגיטימית ותקינה לגמרי.

## מה נשאר לוודא אחרי שזה עובד

תיבת הדואר `no-reply` תקבל תשובות של לקוחות שילחצו "השב". שווה:
- להגדיר לה כלל העברה לתיבה שאתה קורא, **או**
- לשנות ב-WP Mail SMTP את ה-Reply-To לכתובת השירות שלך

וגם: יש באתר תוסף **WP Mail Logging**. אחרי המעבר כדאי לעבור עליו פעם בשבוע בחודש הראשון ולוודא שאין כשלים חדשים.
