## סדר ההרצה

### שלב א׳ — צילום מצב (30 דקות)

1. **גיבוי מלא** (קבצים + DB) לפני כל דבר אחר.
2. להעלות `tools/nama-audit.php` ל-`wp-content/mu-plugins/`.
3. להריץ: **כלים → Nama Audit → הרצת בדיקה מלאה**.
4. להעתיק את ה-JSON מתחתית העמוד ולשמור.
5. אם יש SSH: `bash tools/nama-cli-audit.sh > nama-report.txt`

### שלב ב׳ — מדידת מהירות בסיס (20 דקות)

לפני כל שינוי, לתעד את המצב הנוכחי ב-5 עמודים:
דף הבית, ארכיון קטגוריה, עמוד מוצר, עגלה, תשלום.

- PageSpeed Insights — נייד **וגם** שולחן עבודה
- GTmetrix — לשמור את ה-Waterfall
- Query Monitor — מספר שאילתות וזמן PHP בכל עמוד

הבסיס הזה הוא מה שיוכיח שהתיקונים עבדו.

### שלב ג׳ — אבחון ההזמנות (יום עבודה)

לפי `docs/02-incomplete-orders.md`, בסדר הכתוב.
נקודת ההתחלה החשובה: **שלב 1 — "האם הלקוחות שילמו?"**. השאילתה הזו מפרידה בין שתי בעיות שונות לגמרי ומקצרת את כל האבחון.

להתקין את `tools/nama-checkout-logger.php` ולתת לו 24–48 שעות לאסוף נתונים אמיתיים.

### שלב ד׳ — תיקונים (לפי עדיפות)

1. כל ממצא ב-**קריטי** מהדוח
2. תיקוני ההזמנות מהפלייבוק
3. שלבים 1–4 ב-`docs/03-performance.md`
4. ממצאי **אזהרה**
5. שלבים 5–8 בתוכנית הביצועים

**כלל:** שינוי אחד → בדיקה → מדידה → הלאה. לא לצבור שינויים.

### שלב ה׳ — אימות

- 3 הזמנות בדיקה מקצה לקצה, בדפדפנים שונים, אחת מהן בנייד
- הרצה חוזרת של `nama-audit.php` והשוואה לצילום המצב הראשוני
- מדידת מהירות חוזרת באותם 5 עמודים
- מעקב שבועי אחרי שיעור ההזמנות הלא מושלמות

## כללי בטיחות

1. **גיבוי לפני כל שינוי.** ללא יוצא מן הכלל.
2. **סביבת Staging** לשינויים מבניים: שדרוג PHP, HPOS, החלפת תוסף מטמון.
3. **בשעות עומס נמוכות** — אופטימיזציית DB, שדרוגי תוספים, `wp db optimize`.
4. **אחרי כל שינוי שנוגע בצ׳קאאוט** — לבצע הזמנת בדיקה אמיתית. תמיד.
5. **לא לגעת בשערי סליקה** בלי לתאם עם חברת הסליקה מראש.

---

## מה הכלים לא בודקים

לשקיפות, אלו דברים שדורשים גישה או כלים חיצוניים:

- **Core Web Vitals אמיתיים משדה** — רק PageSpeed Insights / Search Console
- **דירוגי SEO ותנועה** — Search Console + Analytics
- **סריקת נוזקות עמוקה** — Wordfence / Sucuri / MalCare
- **בדיקת נגישות** — axe DevTools / WAVE
- **חוויית משתמש בצ׳קאאוט** — הקלטות מסך (Hotjar / Clarity) חושפות נטישה שאף לוג לא יראה
- **צילוב מול דוח הסליקה** — דורש גישה לממשק חברת הסליקה. **חובה** לביצוע לפני השלמת הזמנות ידנית
