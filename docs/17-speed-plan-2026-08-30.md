# 1. 🔴 WP Rocket — מיזעור ואיחוד. **הצעד הגדול ביותר.**

**אומת: המיזעור כבוי לחלוטין.** אפס חתימות `data-rocket` בקוד. מטמון הדפים כן עובד.

הפעלה תאחד ‎~184 קבצים ל-**‎~10**.

### מה לסמן — WP Rocket → File Optimization

**CSS Files**
- ☑ Minify CSS files
- ☑ Combine CSS files
- ☑ Optimize CSS delivery → **Remove Unused CSS** (מומלץ) או Load CSS asynchronously

**JavaScript Files**
- ☑ Minify JavaScript files
- ☑ Combine JavaScript files
- ☑ Load JavaScript deferred

### ⚠️ החרגות — להזין לפני ההפעלה
ב-**Excluded JavaScript Files** וב-**Excluded from Delay**:
```
woocommerce/assets/js/frontend/checkout
woocommerce/assets/js/frontend/add-to-cart
wc-checkout
wc-cart-fragments
jquery.blockUI
WCGatewayTranzila
yaycurrency
sitepress-multilingual-cms
```

### ⚠️ איך לעשות את זה נכון
1. **גיבוי לפני.**
2. להפעיל **סעיף אחד בכל פעם**, ולבדוק את האתר בין לבין.
3. אחרי כל סעיף: דף הבית, עמוד מוצר, הוספה לעגלה, **וצ׳קאאוט מלא**.
4. `Combine JavaScript` הוא המסוכן ביותר — להשאיר לאחרון.
5. אם משהו נשבר: לכבות את הסעיף האחרון, לנקות מטמון, לבדוק שוב.

> **למה זה לא נעשה מכאן:** להגדרות WP Rocket אין REST API, והן דורשות בדיקה
> ויזואלית אחרי כל שלב. זה 15 דקות עבודה שלך, וזו התמורה הגדולה ביותר ברשימה.

# 2. 🔴 Redis Object Cache — הצעד הגדול בצד השרת

אחרי OPcache נשארו ‎~2,200ms לכל עמוד לא-ממוטמן. הקומפילציה כבר לא הבעיה —
**השאילתות הן.**

1. cPanel → לחפש **Redis**. אם אין — פנייה לאחסון:
   > *"אני צריך Redis server + PHP redis extension עבור הדומיין nama-c.com"*
2. להתקין את התוסף **Redis Object Cache** (Till Krüss)
3. ב-`wp-config.php`, **לפני** `/* That's all, stop editing! */`:
   ```php
   define( 'WP_REDIS_HOST', '127.0.0.1' );
   define( 'WP_REDIS_PORT', 6379 );
   define( 'WP_REDIS_PREFIX', 'namac_' );
   define( 'WP_REDIS_MAXTTL', 86400 );
   ```
   > `WP_REDIS_PREFIX` **חובה** — יש התקנה נוספת על השרת (טבלאות `wpq5_`).
4. Settings → Redis → **Enable Object Cache**
5. **מיד אחרי: הזמנת בדיקה מלאה.** Object Cache שגוי שובר סשנים של עגלה.

# 3. 🟠 ניקוי בסיס הנתונים

`wpgh_options` — **15.3MB נתונים מול 427MB שטח מבוזבז**, ונקראת בכל בקשה.

phpMyAdmin, **אחרי גיבוי**:
```sql
OPTIMIZE TABLE wpgh_options;

DELETE FROM wpgh_options
WHERE option_name LIKE '\_transient\_timeout\_%'
  AND option_value < UNIX_TIMESTAMP();

DELETE FROM wpgh_woocommerce_sessions WHERE session_expiry < UNIX_TIMESTAMP();
```

# 4. 🟡 `nama-speed` 1.2.0 — מה שאני כן יכול לעשות

מסיר **בכל האתר** נכסים שנטענים ואינם בשימוש:

| מה | למה מיותר |
|---|---|
| `wp-block-library` + `-theme` | האתר בנוי ב-Elementor |
| `wc-blocks-style` | הצ׳קאאוט קלאסי, לא בלוקים |
| `classic-theme-styles` | — |
| `global-styles` (theme.json) | Woodmart היא ערכה קלאסית |
| `jquery-migrate` | נדרש רק ל-jQuery מלפני 3.0 |

ומוסיף `preconnect` ל-`fonts.gstatic.com` ו-`fonts.googleapis.com`.

**החיסכון: ‎~6–8 בקשות מתוך 216.** כלומר **‎~3%.**

> **אני אומר את זה במפורש כדי שלא תהיה אכזבה:** התוסף הזה **לא** יפתור את
> המהירות. הוא מגרד בשוליים. **ההשפעה האמיתית היא בסעיפים 1 ו-2.**

### ⚠️ `jquery-migrate` — הפריט היחיד עם סיכון
אחרי ההעלאה **לבדוק:** תפריט נייד · סליידרים · הוספה לעגלה · בורר ווריאציות.
אם משהו לא מגיב — לשנות `'trim_site_wide' => false` ולהעלות מחדש.
